# 영수증 OCR 개선 기록

## 목표

MindOFF의 OCR은 결과를 자동 확정하지 않고, 사용자가 검토할 수 있는 영수증 초안을 만드는 기능이다. 무료 AWS 계정에서 Textract 사용이 제한되어 Tesseract 기반 대체 구현으로 먼저 학습하고, 측정 결과가 목표에 미달하면 Textract 어댑터로 교체한다.

## 1차 구현과 한계

첫 구현은 원본 이미지를 `kor+eng`, `PSM 6`으로 한 번 인식한 뒤 줄 끝 숫자를 금액으로 해석했다.

- 이미지 기울기·대비·해상도 보정 없음
- 영수증 전체를 하나의 텍스트 블록으로 가정
- 텍스트만 사용하고 단어 좌표와 신뢰도는 사용하지 않음
- 품목명·수량·단가·합계 열이 섞이면 정규식이 잘못된 값을 생성

운영 이미지에서 업로드와 실행은 정상 동작했지만 매장명, 날짜, 합계, 품목 열 정확도가 부족했다.

## 2차 개선

```text
비공개 S3 원본 저장
  ├─ 원본 + PSM 6 ───────────────┐
  └─ ImageMagick 전처리 + PSM 4 ─┤
                                  ├─ 신뢰도·영수증 패턴 점수 비교
                                  └─ TSV 좌표 기반 필드 추출
```

전처리는 자동 회전, 흰 배경 처리, 회색조, 크기 정규화, 대비 강화, 선명화, 기울기 보정을 수행한다. 기존 원본 인식도 함께 실행해 전처리가 오히려 글자를 손상시키는 경우를 대비한다.

Tesseract TSV 결과에서 다음 정보를 사용한다.

- 단어별 위치와 크기
- 줄 그룹
- 단어별 신뢰도
- 페이지 분할 방식별 전체 품질 점수

필드 파서는 품목명 앞부분과 숫자 열을 분리하고, 한국 원화 영수증의 `3,000`과 `3.000`을 모두 3,000원으로 해석한다. 지나치게 오래된 날짜, 낮은 신뢰도의 줄, 결제·세금·사업자 메타데이터, 500원 미만의 오인식 금액은 초안에서 제외한다.

## 운영 제약과 선택

현재 ECS 작업은 `0.25 vCPU / 512MB`다. 비용을 늘리지 않고 응답 시간을 유지하기 위해 OCR은 두 번만 실행하며 ImageMagick과 Tesseract의 스레드를 1개로 제한한다. 전체 처리 제한은 45초다.

로그에는 원문이나 품목명을 남기지 않고 다음 진단 정보만 기록한다.

- 선택된 PSM과 전처리 사용 여부
- 평균 신뢰도
- 단어·줄·추출 품목 수
- 매장명·합계 검출 여부

## 검증 기준

동일 이미지 재검증 후, 개인정보를 가린 다양한 영수증 표본으로 다음 프로젝트 목표를 측정한다.

| 항목 | 목표 |
| --- | ---: |
| 구매일 정확 일치 | 90% 이상 |
| 합계 금액 정확 일치 | 90% 이상 |
| 매장명 검토 가능한 수준 | 80% 이상 |
| 품목명·금액 행 검출 | 80% 이상 |
| 처리 시간 | 45초 이내 |

목표에 미달하면 전처리와 파서에 예외 규칙을 계속 쌓기보다, 현재 유지 중인 Textract `AnalyzeExpense` 어댑터로 전환한다. Tesseract 실험은 실패가 아니라 OCR 전처리, 레이아웃 분석, 신뢰도 기반 폴백을 학습하고 서비스 선택 근거를 만든 과정으로 남긴다.

## 개인정보 처리

- 원본 이미지는 공개 접근이 차단된 S3에 암호화 저장
- OCR 임시 이미지와 TSV는 요청 종료 시 삭제
- OCR 원문은 로그에 기록하지 않음
- 낮은 신뢰도의 결과는 자동 반영하지 않고 사용자 검토 후 확정
